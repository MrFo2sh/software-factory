## Idea
Agent Globe proved that a live 3D constellation, an attention queue, sounds and cards make agent
work playable. GEE is the general version, in two parts:

1. **Engine kit (`products/gee`).** The domain-free parts of agent-globe moved into a reusable
   Rust crate set: event model and reducer, orbital layout, bridge (file tail + HTTP ingest on
   localhost), HDR orbit camera, units/rings/halos/beams scene, egui HUD, sidebar with the Needs-You
   queue, unit panel with a timeline, floating cards, sounds, persisted settings, and gamification
   primitives (XP, levels, streaks, badges). A domain plugs in through one `Domain` trait: what the
   units are, what feeds them, what needs the user, what earns XP.
2. **Playbook.** An `AGENTS.md` so any agent that opens the folder can take a user prompt
   ("gamify my SOC", "gamify my homelab", "gamify my bug bounty notes") and build a full environment
   from a template, without repeating agent-globe's mistakes.

Plus a factory blueprint `gamified-env` so new environment ideas are built on the kit.

## Stack (not negotiable)
Rust + Bevy (wgpu) + bevy_egui, same versions as agent-globe. Environments must stay at 60 fps with
thousands of live objects; browsers and Electron are out.

## Must have
- Engine crates compile and test without a domain; `data` layer has no Bevy imports.
- One example environment built only through the playbook: a blue-team SOC desk fed by
  Suricata `eve.json` (JSONL) or HTTP ingest, with a demo replay so it runs with no sensor.
- `envs/_template` + a script that copies it to a new environment.
- Factory blueprint `gamified-env` and a decision-table row.

## Constraints
Defensive only. Red-team environments organize an authorized engagement's own notes and tool
output; the kit ships no attack tooling.
